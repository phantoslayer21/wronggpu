## Vectors

Only `manifest.json`, `SHA256SUMS` and `.gitignore` of `tests/vectors/` are committed: the binary files would fail the
clean-repo content scan (binary / size rules), so they are regenerated by `gen_vectors` (deterministic; `check_vectors`
verifies every file against `SHA256SUMS` and re-runs the reference; `test_vectors` regenerates and compares).
`tests/vectors/manifest.json` lists every file with dtype (`e4m3` = uint8 codes, `f16` = little-endian bit
patterns, `u8` = mask), shape and layout (`[Y][X][C]` tensors; per-window intermediates `[w][...]` with window
index `w = j*nwx + i`, token `t = 8*ly + lx`).

- `tables/`: Q8 of every f16 pattern, d8 of every code, sigmoid (+ near-midpoint mask), reciprocal, and for each
  window-constant set (`A`, `B`, `zovf`) the attention weight of every f16 score and the activation of every f16.
- `weights/<stage>[-hot]/`: one synthetic logical weight set per stage kind (51.2 shapes), `-hot` = stress set.
- `cases/<stage>_r<Wt>x<Ht>[...]`: per stage kind, level extents from the render token sizes 32x32, 64x96, 160x96,
  288x256 (up to 1,536 tokens), shifts (6,6), (2,4), (0,0), (4,2); cases where every extent read is at least 8
  (single reflection) and below 8 (repeated reflection) are marked in `border_rule`. Inputs, expected outputs
  (`y2`, `merged`, `hnew`, `hmerged`), the row sums `Z` of every window, sigmoid-tolerance masks, and a full trace
  (q, v, s, P, O, Dp, y1h, y1q, Du, Au, Dd, y2h, xf, upq, Dh, u) for the first two windows of the smallest case of
  each stage and of every stress case.
- Tolerances (per output in the manifest): bit-exact (e4m3 zero codes equal) when the stored `Z` is supplied
  (51.8 item 1); with an implementation's own f32 row sums P may differ by one code in rows whose Z differs
  (51.3 step 4); hidden outputs additionally allow the sigmoid tolerance of 51.4 on flagged tokens; the matrix
  step must round once per 32 inputs (51.1).

## Converted model files (2026-10-20, track "converter")

`clean/converter` now converts preset F (map version 5, page 57): `wronggpu-convert --map <preset-F map> --dll
<the player's RR library> --out <dir>` writes `model.wgcm` (container version 2, `clean/converter/OUTPUT-FORMAT.md`).
`model/model_file.py` loads it for the runtime: `admit_model_file(path, map_path=None)` checks the whole-file hash,
recomputes every group digest with the stored key (57.7.3), checks the page-56.4 / 57.7 inventory (and, with the
map, every group digest against the map) and returns an `AdmittedModel` (variant B1 / B2 from `constants_b2`,
symbol table, shifts per parity, per-stage ra/m/f/g, window constants, NumPy weights in the reference stages'
shapes). Standard library only; NumPy only for `stage_weights_numpy` / `catalog_bindings`.
`tests/test_model_file.py` converts the spec team's synthetic 57-T8 files (both IMG-IN variants) and loads them.
The older `validate_metadata` (synthetic known subset) is unchanged and still blocks "complete_player_model"
requests; the model-file path is the player-model path.

## Integration: one connected frame sequence (2026-10-20, branch `clean/rr-f-int`)

`gpu/sequence.py` runs PH2 pool -> exposure -> input stage -> body -> head -> widening -> output stage -> extended
resolve per frame, one submission per frame on a resident arena (`rr_host` `checkpoint`), with every temporal image
(EX, PM pair, Pe, Pn, HID, CH pair, PH1, PH2, TH / AH) produced on the GPU, the lifecycle reference planning the
frames (resets, render-size change and back), and the weights / symbols of a converted model file
(`--model <model.wgcm>`, default the converted B2 stand-in) or own network-like values (`--synthetic`). Each stage
is compared with its reference on the GPU's upstream values; `--mutation hid|pm|ch|exposure|ph1` must fail;
`--bench <render>:<output>` times one frame without reset at a game size. Results and timings:
`results/2026-10-20-rr-f-integration.md`; provisional readings: `QUESTIONS-INT.md`.

```
set WG_RR_BUILD=<build>\rr-f-int\kbuild
python -m clean.rr_f.gpu.sequence --json seq.json
python -m clean.rr_f.gpu.sequence --synthetic --json seq-synth.json
python -m clean.rr_f.gpu.sequence --bench 1706x960:2560x1440 --step E --zmode f32 --json bench.json
```
The runtime library `wronggpu_rr_runtime.dll` (owned adapter of the proxy, the whole preset-F frame recorded into the
game's command list, page-53 state, timing log) is under `runtime/` (README there; results
`results/2026-10-20-rr-runtime.md`). Since branch `clean/rr-f-rt-int` it runs the integration frame above (PH2 pool,
exposure, input stage with the game's inputs read through SRVs, body, head, output stage, extended resolve, stores into
the game's outputs), loads the converter's `model.wgcm` itself and places its work buffers by their lifetimes; results
`results/2026-10-20-rr-rt-int.md`.
