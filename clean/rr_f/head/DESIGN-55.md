# DESIGN-55 - D0-R and the output head of spec 55 on RDNA 4 / D3D12

Status: design 1 with a working kernel (clean team, branch clean/rr-f-head). Sources: spec 55 draft 7 and spec 51
draft 6 only; conventions from the Model M D3D12 ports (`clean/dx12/`: README, `hlsl/wg_platform.hlsli`,
`hlsl/wg_ags.hlsli`, `kernels/swin_common.hlsli`, `kernels/speed_swin.hlsli`) and DESIGN-51 (clean/rr-f, design only:
when this was written the window-block kernels of that branch did not exist yet, so the block is written here for
C = 32 following DESIGN-51's mapping; nothing of clean/rr-f's working tree is copied). Open points: `QUESTIONS-55.md`.

## 1. Summary

* **One dispatch for the whole stage**: one workgroup = one 8 x 8 window of the shifted grid of 51.6 (shift
  ((s + 4) mod 8) of D0's SH row, provisional Q2), 4 waves of 32 lanes, wave w = window rows 2w, 2w + 1. The block
  (51.3, C = 32, H = 2, MLP 128) leaves y2h in registers and the head (55.2, 55.3) runs on it directly: D0-R never
  writes y2 (55.1) and no tensor between block and head goes through memory.
* **88 FP8 WMMAs per wave** (`v_wmma_f32_16x16x16_fp8_fp8` through the driver channel `wg_wmma_fp8`), every 51.1
  matrix step = two WMMAs on an f32 accumulator, then one RNE conversion to f16. One LDS exchange (q and v^T of both
  heads, 8 KB) and **one barrier** per window; all weights (14 KB) read from global memory in fragment order (they
  stay in the caches).
* **Exact pieces by construction**: the attention weight in packed f16 + two integer instructions
  (`bits(w) = (bits(p) << 5) & 0x7fe0`), r = R(1/Z) by `v_rcp_f32` + RNE, the sigmoid and R(tanh) by the exact 65,536-entry
  tables, rho by a 65,536-entry table built for the model's s2 (rho depends on the f16 y17 only), the PREC products in
  f32 as written, every f16 rounding point one hardware rounding.
* **Not exact by construction**: (a) Z is summed in f32 (spec 51.3 step 4 accepts it; a supplied-Z variant tests the
  rest), (b) the f32 accumulation inside / between the two WMMAs of a step (51.1 last sentence; measured below),
  (c) CANDW's logistic (~2 f32 ulp, spec tolerance 3 f16 steps).
* **Result**: bit-exact Cnet / HID / GATES / PREC and y2h on 7 of the 8 vector cases, CANDW within 1 f16 step (codes
  identical to the reference); the adversarial `stage_edge` case (every finite e4m3 code) exceeds the tolerance on 13
  values because the FP8 WMMA accumulates in f32 per group of 8 products (measured, section 6). 120 VGPRs, 8 KB LDS,
  **1.015 ms** at 1440p Quality (median of 200; 26,257 windows).

## 2. Buffers (the runtime's own layouts; arena byte offsets, as the M ports)

| buffer | layout | bytes per token / size |
|---|---|---|
| x (D0-F output) | e4m3 `[Ht][Wt][32]`, natural channel order | 32 |
| weights | 56 fragments of 256 B: Wq [h][ft][ks], Wv [h][ft][ks], Wo [h][ct][ks], W1 [nt 8][ks 2], W2 [ct 2][ks 8]; lane l, byte i = W[16 ks + 8 (l >> 4) + i][16 nt + (l & 15)] | 14,336 |
| biases | f32 copies of bo, b1, b2 (exact widening, read as C fragments) | 768 |
| score bias | the 12 Tb blocks expanded at load time to the C fragments of all 16 (I, J) blocks: f32 `[h][I][J][lane][8]`, value B_h(16 I + (l & 15), 16 J + 8 (l >> 4) + i) | 32 KB |
| hold (IN0 hnew) | f16 `[Ht][Wt][4]` | 8 |
| Hc (D1-R hnew) | f16 `[Ht/2][Wt/2][4]` | 8 (level 1) |
| tables | sig of 51.4 (f16 [65536]) then R(tanh) (f16 [65536]); rho (f32 [65536]) for the model's s2 | 512 KB |
| Cnet | f16 `[Ht][Wt][4]` (every tensor token, Q3) | 8 |
| HID, GATES, CANDW | one 32-bit texel `[Hr][Wr]` (bytes = values 0 .. 3: the R8G8B8A8 SNORM / UNORM texel) | 4 each |
| PREC | `[Hr][Wr]` x 4 f16 (the R16G16B16A16_FLOAT texel) | 8 |

The tables are model-load-time data: sig and R(tanh) are constants of the spec (generated by the exact scalar
evaluation; here the vectors' exhaustive tables are loaded), rho is `tanh32(f32(v s2))` correctly rounded for every f16
v, recomputed whenever s2 changes (once per model). The images are written as raw buffers with the texel layouts above;
binding them as typed textures for page 54 is a runtime choice (page 54 not available).

## 3. The block at C = 32 (51.3 on v_wmma_f32_16x16x16_fp8_fp8)

Fragments (wave32): lane l, r = l & 15, hf = l >> 4. A = row r, K 8hf .. 8hf+7; B = column r, K 8hf .. 8hf+7; C / D =
column r, rows 8hf .. 8hf+7. Activations are "channels x tokens" D tiles: lane (r, hf) of channel tile ct holds channels
16 ct + 8 hf .. +7 of token r - the same bytes as the B fragment of K-slice ct. So x is loaded as two 8-byte reads
(channels 8hf.. and 16 + 8hf..), which serve as B (q), A (v, transposed) and the residual base of step 7 alike.

| step | A | B | C (start) | WMMAs per wave |
|---|---|---|---|---|
| q_h | Wq_h^T (2 feature tiles) | x | 0 | 8 |
| v_h^T | x | Wv_h | 0 | 8 |
| s_h | q of key tile J (LDS) | own q | score bias (f32) | 16 |
| O_h | v^T of key tile J (LDS) | P | 0, then step 1's f16 | 16 (keys 0-31, then 32-63) |
| Dp | Wo_h^T | O_h | bo, then head 0's f16 | 8 (chain h = 0, 1) |
| Du_j | W1 chunk j | y1q | b1 chunk | 16 |
| Dd | W2 chunk j | Au_j | b2, then chunk j-1's f16 | 16 (chain j = 0 .. 3) |

The score tile has keys as rows and the wave's queries as columns: a lane holds 8 keys x 4 key tiles of one query,
the row sum is 16 `v_dot2_f32_f16` plus one lane ^ 16 exchange, and the P tile is directly the B operand of P V.
Q8 after q, v, O, y1q and Au: one wave-uniform test (`sw_absmax8` / `sw_in448`, speed_swin.hlsli) skips the clamp
when nothing in the wave exceeds 448; otherwise `sw_pack_q8_v2` (clamp, NaN kept). NaN codes come out as 0xff (the
hardware's NaN): a NaN code's sign never reaches an output (every later use is a product or a NaN-propagating sum), so
in-network NaN signs are not reproduced (spec 51.1 gives the sign of h; not observable here).

### Rounding points (spec -> instruction)

| spec | value | implementation |
|---|---|---|
| 51.1 step | R(C + 32 products) | 2 WMMAs on f32 C, `v_cvt_f16_f32` (driver conversion, RNE); next step / Q8: `v_cvt_f32_f16` (exact) |
| 51.3 s3 | u = R(s A_SCALE), clamp, R(A_P1 - c c), p | `v_pk_mul_f16`, `v_maxmin_num_f16` (NaN -> A_CLAMPn), 2 x `v_pk_fma_f16` |
| 51.3 s3 | w | `(bits(p) << 5) & 0x7fe07fe0` (exact, valid in the converter-checked range) |
| 51.3 s4 | Z | f32 (`v_dot2_f32_f16` with (1, 1), partner lane added), RNE to f16 (software `wg_f2h`) |
| 51.3 s4 | r, P | `v_rcp_f32` + RNE (exact: DESIGN-51 8.3), `v_pk_mul_f16(w, r)`, fence, widen, FP8 pack (P <= 1 + 2^-11, no clamp) |
| 51.3 s7, s9 | y1h, y2h | `v_pk_fma_f16(Dp, ra, d8(x))`, `v_pk_fma_f16(Dd, m, y1h)` |
| 51.3 s8 | act | clamp (`v_maxmin_num_f16`), `v_pk_fma_f16` x 2, `v_pk_mul_f16`, fence, widen, Q8 |
| 51.4 | sig | table |
| 51.4 / 55.2 | gate, omz, bilinear, hh, hnew | `v_pk_mul_f16` / `v_pk_add_f16` / `v_pk_fma_f16`, each rounding point fenced; hnew_3 = fma(hold_3, omz, -0) = R(hold_3 omz) |
| 55.3 | Px, Py, sq, (Px Py) rho | f32 multiplies as written (fenced against regrouping by s1), one RNE to f16 |
| 55.3 | d, CANDW | `f32(la) - f32(lb)` (one rounding; la, lb = y10, y12 per the page 55 erratum), `0.5 / (1 + e^-d)` with a split exponent argument and one Newton step on `v_rcp_f32`, RNE to f16 |
| 55.3 | codes | unorm8: min / max (NaN -> 0), x 255, `v_rndne`; snorm8: NaN -> 0, clamp, x 127, `v_rndne` |

**Driver hazard found here** (in addition to clean/dx12/README.md's list): the opaque-zero fence of the M ports
(`x ^ (wg_grid_ >> 31)`) protects f32 values only. For a packed f16 pair the compiler knows that the high 16 bits of
that zero are 0, so the fence is transparent for the high half: the widening of `v_pk_fma_f16`'s high result was
folded into a `v_fma_mix_f32` (no f16 rounding: wrong Q8 inputs). The fences of this kernel XOR with
`0 - (wg_grid_ >> 31)` (no known bits). After the change the ISA has exactly one `v_fma_mix_f32`: `y20 - y24`, which
is an exact difference rounded once (the spec's d).

## 4. The head (55.2, 55.3): two lanes per token, each writes half of every texel

After step 9 lane (r, hf) holds y2h channels 8hf .. 8hf+7 and 16 + 8hf .. +7 of token r (natural numbering):
hf 0 has y0 .. y7, y16 .. y23, hf 1 has y8 .. y15, y24 .. y31. The head reads, per the page 55 erratum
(`RR_P55_ERRATUM 1`, default): gate logits g0..g3 = y0, y1, y2, y3; GATES G0..G2 = y4, y5, y6; PREC px, py, rho =
y7, y8, y9; CANDW d = y10 - y12; HID ha = y14 (values 0, 1), hb = y16 (values 2, 3). Two lane ^ 16 exchanges of
y2h words first give each half the words of its role (hf 0 receives (y8, y9), (y10, y11); hf 1 receives (y4, y5),
(y6, y7)); `RR_P55_ERRATUM 0` (page 55's printed numbers, comparison only: g = y0, y1, y4, y5; G = y8, y9, y12;
px, py, rho = y13, y16, y17; d = y20 - y24; ha = y28, hb = y2) has every role word local and skips them. The rest is
one instruction stream for both modes; the two halves run it on different data (divergence only at the GATES / PREC
stores):

| | hf 0 | hf 1 |
|---|---|---|
| table loads | sig g0, g1, g2, g3, py; tanh hb; rho(rho) | sig G0, G1, G2, px; tanh ha |
| one lane ^ 16 exchange (2 dwords) | sends (sig g2, sig g3), la | sends (sig px, lb) |
| Cnet (55.2) | channels 0, 1 (gates sig g0, g1) | channels 2, 3 (gate sig g2; channel 3 = R(hold_3 omz)) |
| CANDW | w = R(sigx(d)/2) -> values 0, 1 | w' = R(sigx(-d)/2) -> values 2, 3 |
| HID | values 2, 3 (tanh hb) | values 0, 1 (tanh ha) |
| PREC | values 1, 2, 3 (Py^2, (Px Py) rho, 0) | value 0 (Px^2) |
| GATES | - | the whole texel |

Every texel half is a 16-bit store (`buffer_store_b16`), so no lane needs the other lane's result. CANDW's pair
identity holds by construction (one value written twice); d = 0 gives 0.25 exactly; `d = +-inf` gives (1/2, 0) / (0, 1/2)
(the exponent argument is clamped to [-100, 87], where e^t is finite and the f16 result is already 0 or 1/2); NaN
propagates by a final select. Bilinear weights: 3/4 for the floor + 1 neighbour at even X (Y), coarse reads at
`(X - 1) >> 1` and + 1, reflected at the level-1 extent (Q4).
Writes: Cnet for 0 <= X < Wt, 0 <= Y < Ht; images for 0 <= X < Wr, 0 <= Y < Hr (other tokens write nothing).

## 5. Test host and procedure

`run_dx12.py build` compiles 5 variants (prod; dbg = prod + diagnostic writes of y2h, Z and the f16 values of HID /
GATES / CANDW; dbgz = dbg with the vectors' reference Z read instead of computed; head / headprod = head only, y2h
given) and the host; `prepare` writes one job per (case, variant) - the arena image (inputs, tables, output regions
filled with a sentinel plus a 256-byte guard after each) and the 38 argument DWORDs; `gpu` runs them under the GPU
lock; `compare` applies the manifest's rules: f16 steps per output (Cnet / HID / GATES / PREC <= 1, CANDW <= 3), codes =
store rule of the kernel's own f16 values (exact) and against the reference codes (counted), CANDW exact requirements,
y2h bit for bit with the reference Z (51.8 item 1, first run), own Z against the reference Z (counted), prod bytes =
dbg bytes, every guard and unwritten byte untouched. Timing: render 1706 x 960 (1440p Quality), tensor 1728 x 960,
shift (2, 2) (26,257 windows), synthetic weights / inputs in the distribution of `stage_basic`, 3 s warm-up, median of
200 dispatches by GPU timestamps.

## 6. Results (RX 9070 XT, gfx1201, D3D12, 2026-10-18; `run_dx12.py`, report.json in the work folder)

**Build** (RGA, prod variant): 120 VGPRs, 36 SGPRs, 8,192 B LDS, no scratch, 21 KB ISA, 88 WMMAs, 7 stores; one
`v_fma_mix_f32` (the exact-then-rounded d). Occupancy: VGPR-bound, 12 waves per SIMD = 6 workgroups per CU (LDS
would allow 8). Debug variants 113-118 VGPRs; head-only 25.

**Vectors** (values differing from the reference / largest difference in f16 steps; "own Z" = the production
arithmetic, the run 55.5 describes; the reference-Z run gives the same numbers except where noted):

| case | verdict | Cnet | HID | GATES | PREC | CANDW | codes vs reference | y2h (own Z / ref Z) | Z rows differing |
|---|---|---|---|---|---|---|---|---|---|
| stage_basic | tolerance | 0 | 0 | 0 | 0 | 4 / 1 | 0 | 0 / 0 | 0 of 3,200 |
| stage_border | exact | 0 | 0 | 0 | 0 | 0 | 0 | 0 / 0 | 0 |
| stage_shift | tolerance | 0 | 0 | 0 | 0 | 4 / 1 | 0 | 0 / 0 | 0 |
| stage_zovf | tolerance | 0 | 0 | 0 | 0 | 2 / 1 | 0 | 0 / 0 | 0 (incl. the Z = +inf rows) |
| stage_edge | **failing** | 0 | 6 (NaN / +-1 vs other) | 0 | 7 (NaN vs number) | 0 | HID 6 | 50 / 51 | 280 of 3,200 |
| stage_nan | exact | 0 | 0 | 0 | 0 | 0 | 0 | 0 / 0 | 0 |
| head_edge | tolerance | 0 | 0 | 0 | 0 | 30 / 1 | 0 | - | - |
| head_random | tolerance | 0 | 0 | 0 | 0 | 2 / 1 | 0 | - | - |

In every case: codes = the store rule applied to the kernel's own f16 values (0 differences), CANDW pairs identical,
equal logits -> 0.25 (73 tokens), infinite / NaN d cases correct (1,966 tokens), no texel outside Wr x Hr written,
every guard byte untouched, prod bytes = dbg bytes (head-only: headprod = head).

**stage_edge, the cause.** 29 of 1,024 tokens differ, always as a cascade (one quantised intermediate one code off, then
the all-codes weights amplify it up to inf / NaN). An emulation of the block with other accumulation models of the
51.1 step (`work/an/emu.py`, not committed: analysis only) against the kernel's y2h with the reference Z:
exact step (the spec) 51 values differ; f32 rounding after each WMMA (16 products + C) 17; **f32 rounding after C and
after every group of 8 products** (K 0-7, 8-15 of each WMMA) **2**; groups of 4: 19; truncation: 52. So the FP8 WMMA
of this driver / chip behaves as f32 accumulation per 8 products (DESIGN-51 probe P1's question, hypothesis H-exact
rejected). With the normal-distributed weights of the other cases every step is exact in that model, and the kernel is
bit-exact there. The Z rows of stage_edge differ mostly through the scores (20 of the 280 rows remain against the exact
sum of the kernel's own w: the f32 Z order). Spec 51.1 ("can only be judged on hardware", 51.7 item 3) leaves this
open: QUESTIONS-55 item 15.

**CANDW**: 42 values one f16 step off over all cases (the ~2-ulp f32 logistic near f16 midpoints; spec tolerance 3,
provisional), no code changed.

**Time at 1440p Quality** (render 1706 x 960, tensor 1728 x 960, shift (2, 2): 217 x 121 = 26,257 workgroups, 3 s
warm-up, 200 dispatches, GPU timestamps): **median 1,014.96 us**, min 954.96, mean 1,010.35. Head-only kernel (y2h read
from a 106 MB buffer instead of computed, same head code): 293.7 us, about DRAM-bound (~170 MB moved). DESIGN-51's
estimate for the D0-R core alone was 0.84 ms +-40 %. The fused kernel moves about 115 MB (x 53, hold 13, Hc 3, outputs 46).

**Levers** (not done): the f32 <-> f16 conversions dominate the VALU stream (365 `v_cvt_f16_f32` + 345
`v_cvt_f32_f16` static, 8 + 8 per tile and step); a WMMA-free round trip for the steps whose result only feeds Q8
(q, v, O, Au: Q8 of the f16 rounding computed from the f32 bits with integer RNE at bit 13) could remove a third of
them; VOPD pairing of the attention's integer work; two windows per wave to halve the weight loads; the 6 -> 8
workgroups per CU needs <= 96 VGPRs.

## 7. Open points (QUESTIONS-55 items 11-15)

* Exactness of the matrix step on the hardware (item 15): an exact variant needs either integer recomputation of the
  steps whose f32 sum is not provably exact (DESIGN-51's variant X) or operand splitting; neither is implemented.
* Z in f32 (item 11), NaN code signs (item 12), image formats (item 13), the rho table (item 14).
* clean/rr-f's window-block kernels (DESIGN-51 file plan) did not exist when this was written; when they land, the
  block part of `rr_d0r.hlsl` should be cross-checked against them (both are written from the spec independently).
